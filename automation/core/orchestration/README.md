# Content Production Orchestrator

AUT-015 coordinates the existing HCTI bridge and AUT-014 Distribution Executor. It is inactive and supports only approved-render reuse followed by transport-disabled preflight. The checked-in workflow is `automation/n8n/workflows/INT-AUT-015-content-production-orchestrator-dev.workflow.json`.

`content-production@1.0.0` accepts one format request, or a bounded batch of up to four distinct format requests for one package/story. Each request supplies `content_package_id`, `story_object_id`, `requested_format`, `render_policy`, `distribution_mode`, four explicit approval-context booleans, and the four zero-valued budgets. Runtime validation is in `content-production.mjs`. Duplicate formats, mixed packages, ambiguous output identity, positive budgets, `render_missing`, and `controlled_publish` fail closed.

The parent resolves canonical outputs and invokes `hcti-reuse@1.0.0` in HCTI, then `distribution-preflight@1.0.0` in AUT-014. These contracts are version-checked at entry and return. HCTI preserves the existing rendering implementation; its reuse path has no connection to provider transport. AUT-014 resolves every asset, checks canonical visual approval and ordered media, produces six explicit platform plans, and persists before returning. Caller approval assertions cannot replace canonical approval records. Both child workflows restrict callers to AUT-015.

The carousel remains one output with seven immutable ordered assets. Unsupported platform plans retain the whole media set and are marked ineligible. No truncation, slide-by-slide fallback, new render, comment, publication, retry, or idempotency reset is part of this interface. Later live orchestration stages are deliberately blocked until their approvals and atomic backend are proven; this release does not implement an authorized live production path.

`workflow_runs` remains the durable ledger. Its existing JSON ID columns remain arrays. The existing structured `error_message` audit-envelope convention carries format, hashes, approval references, target plans, child workflow/execution references, counters and next-action state; `error_class` is empty for successful preflight. Parent and child run IDs use canonical INT-RUN ULIDs. Re-executing a zero-call preflight records a new audit execution without changing publication claims.
